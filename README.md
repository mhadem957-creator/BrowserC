# Privacy Browser

A cross-platform, privacy-focused mobile browser built with Flutter and
`flutter_inappwebview`. It ships with no built-in content restrictions,
routes address-bar searches through a self-hostable **SearXNG** instance,
includes a lightweight ad/tracker blocker, and helps you configure secure
**DNS-over-HTTPS**. CI builds a release APK automatically on every push to
`main` via GitHub Actions — no local Android Studio setup required to get
an installable APK.

## Features

- Full address bar with automatic URL-vs-search detection
- Search terms are redirected to a configurable SearXNG instance
- Standard navigation: Back, Forward, Reload/Stop, Home
- Simple multi-tab browsing (each tab keeps its own history)
- Built-in ad and tracker blocking (editable domain lists, toggle each independently)
- Secure DNS-over-HTTPS lookups + one-tap shortcut to Android's system-wide Private DNS setting
- Desktop-site toggle, JavaScript toggle, one-tap "clear all browsing data"
- GitHub Actions workflow that builds a release APK on every push to `main`

## Why there's no `android/` folder

The native Android project (`android/`) includes a Gradle wrapper **jar** —
a small binary bootstrap file generated by the Flutter tooling itself. It
can't be hand-written, and committing one at the wrong Flutter/Gradle
version is a common source of "works on my machine" CI breakage. Instead:

1. CI runs `flutter create --platforms=android --org com.privacybrowser .`
   to generate a fresh `android/` folder that matches the exact Flutter SDK
   version the workflow just installed.
2. `scripts/patch_manifest.py` then patches the generated
   `AndroidManifest.xml` with the two permissions the browser needs
   (`INTERNET`, `ACCESS_NETWORK_STATE`), sets the app label, and disables
   cleartext (plain HTTP) traffic by default.
3. `flutter build apk` proceeds as normal.

This is why `android/` is listed in `.gitignore`. If you'd rather commit a
native project and customize it by hand (e.g. to add a custom launcher
icon, change `minSdkVersion`, or add Play signing), just remove those two
lines from `.gitignore`, run the same `flutter create` command locally
once, commit the result, and drop the "Scaffold Android platform folder"
step from the workflow.

## Local development setup

1. Install the [Flutter SDK](https://docs.flutter.dev/get-started/install) (stable channel) and Android SDK/platform tools.
2. Clone this repo and generate the Android platform folder once:
   ```bash
   flutter create --platforms=android --org com.privacybrowser --project-name privacy_browser .
   python3 scripts/patch_manifest.py
   ```
3. Install dependencies and run:
   ```bash
   flutter pub get
   flutter run
   ```

## Building the APK via GitHub Actions

Push to `main` (or trigger manually from the **Actions** tab — the
workflow has `workflow_dispatch` enabled). `.github/workflows/build_apk.yml`
will:

1. Check out the repo and set up JDK 17 + Flutter (stable).
2. Regenerate `android/` and patch the manifest (see above).
3. Run `flutter pub get`, `flutter analyze` (non-blocking), and `flutter test`.
4. Run `flutter build apk --release --split-per-abi`, producing one APK per
   CPU architecture (smaller downloads than a universal APK).
5. Upload the APK(s) as a workflow artifact named
   `privacy-browser-apk-<run number>` — download it from the run's
   **Summary** page.

The release APK is signed with the Flutter debug keystore, which is fine
for sideloading/personal use but **not** for Play Store distribution. For
a real release signing key, generate a keystore, store it (and its
passwords) as GitHub Actions secrets, and add a `signingConfigs.release`
block to `android/app/build.gradle` (which you'd then need to commit — see
"Why there's no `android/` folder" above) that reads those secrets.

## Configuring your own SearXNG instance

Any text typed into the address bar that doesn't look like a URL is sent
to your SearXNG instance as `<searxngUrl><url-encoded query>`. You can
change it two ways:

- **At runtime (no rebuild):** Settings → Search → "SearXNG search URL".
  Enter the full endpoint, ending right at the query parameter, e.g.:
  ```
  https://searx.mydomain.com/search?q=
  ```
- **As the new default for fresh installs:** edit `defaultSearxngUrl` in
  `lib/utils/constants.dart` before building.

If you don't already run SearXNG, see the
[SearXNG docs](https://docs.searxng.org/) for self-hosting instructions
(Docker Compose is the fastest path). Using a public instance like
`searx.be` works too, but a self-hosted instance is what actually keeps
your searches private from a third party.

## Secure DNS: what this app can and can't do

Android's WebView resolves hostnames using the **device's** network stack,
not this app's own networking code — there's no public WebView API that
lets an app override DNS for pages it renders. So:

- The in-app **DoH lookup** (Settings → Secure DNS) is a real
  DNS-over-HTTPS client (`lib/services/dns_service.dart`) useful for
  pre-validating/resolving a typed domain and diagnosing DNS-based
  blocking — but it does not, by itself, change how the WebView resolves
  hosts.
- To make secure DNS apply to **everything** you browse (in this app and
  every other app), use Android's built-in **Private DNS** feature
  (Settings → Network & Internet → Private DNS, Android 9+). Tap
  "Open system Private DNS settings" in this app's Settings screen to jump
  straight there, and enter a DoH/DoT hostname (e.g. `1.1.1.1` for
  Cloudflare, `dns.quad9.net` for Quad9).

## Ad & tracker blocking

Blocking is implemented via `flutter_inappwebview`'s cross-platform
`ContentBlocker` API, driven by two plain-text domain lists in
`assets/adblock/`. Add or remove a domain per line (comments start with
`#`); toggle each list independently from Settings. These are intentionally
small, human-auditable starter lists — swap in a larger list if you want
more aggressive blocking.
